## 阅读顺序（新会话 / 新接手）

1. `进度.md` —— 现在在哪、下一步
2. `协作规范.md` —— 规则与交付格式（**动手前必读**）
3. `PRD.md` + `architecture.md` —— 为什么这么设计
4. `task-cards/` 里当前那一步的规格 —— 照着敲
5. 概念断链时回 `串讲.md`（把零件串成一条线）；要业务全景看 `assets/*-flow.html`

## 三条约定

- **业务定位先于实现细节**：任何规格 / 讲解先写"它是谁 / 在请求的第几步被用到 / 坏了会怎样"，再写签名与流程（见 `协作规范.md §2`）。
- **文档是声明，工件是事实**：进度与状态一律回仓库核对（git / 文件树 / 实跑），不采信任何"已完成"的口头结论。
- **历史不删只归档**：`archive/` 是证据仓库，日常不读；需要时按索引翻。
