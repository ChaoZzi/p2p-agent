## 0. 这一卡要证掉什么

P0-01 唯一的目的是干掉本项目最大的技术假设：**Java + Python 双语言链路不卡壳**。具体证三件事：

1. Java 侧 mock 服务能起、契约端点可用、契约能导出；
2. **Python 生成的 trace_id 穿过 HTTP 边界后，在 Java 响应头和 Java 日志里是同一个 uuid**（本卡核心）；
3. `request_id` 幂等语义在真实数据库里落地——重复请求不产生第二条记录。

所以这一卡没有 LLM 调用、没有状态机、没有审批流：只有**契约、透传、幂等、故障开关**四块地基。地基不牢，P0-02 的主链路就是空中楼阁。

## 3. 契约（钉死的部分，一眼可核）

| 端点 | 请求 | 响应 |
|---|---|---|
| `GET /healthz` | 头 `X-Trace-Id`（可选） | `200 {"status":"ok"}` |
| `POST /api/mock/oa/approvals` | 头 `X-Trace-Id`、`X-Request-Id`；体 `request_id/flow_id/title/amount/applicant` | `200 {"approval_id":"oa-<8>","status":"PENDING","created_at":"<ISO8601>","dedup":false}`；重复 → `dedup:true` + 头 `X-Dedup: true` |
| `PUT /api/mock/faults` | 体 `{"timeout_ms":5000,"random_delay":false}` | `200 {"timeout_ms":5000,"random_delay":false}` |
| `GET /api/mock/faults` | — | `200 {"timeout_ms":0,"random_delay":false}` |
| `GET /v3/api-docs` | — | springdoc 生成的 OpenAPI 3.1 契约 |

统一错误体（任何错误都是这个形状，含 trace）：

```json
{"error":{"code":"VALIDATION","message":"request_id is required","trace_id":"<uuid>"}}
```

- 缺必填字段 / 缺请求头 → `422` + `VALIDATION`
- 状态机非法流转 → `409` + `FLOW_STATE_CONFLICT`（P0-01 无状态机，`ErrorCodes` 里已占位）

## 4. 逐文件讲解（作用 / 关键决策 / 改了会怎样）

### 4.1 Java 侧

**`java-service/pom.xml`** — 手写的最小 Boot 3.5.16 工程（start.spring.io 本机不可达），只引 web / jdbc / sqlite-jdbc / springdoc / test。关键决策：`java.version=21`；给 `spring-boot-maven-plugin` 配 `workingDirectory=${project.basedir}`。**改了会怎样**：删掉 workingDirectory，SQLite 路径会跟着「你在哪个目录敲 maven」漂移，`data/mock-oa.db` 会散落在仓库各处，而证据里那行启动日志也会指向别处。

**`src/main/resources/application.properties`** — 端口 8000、SQLite 连接（`busy_timeout=5000`、连接池=1）、schema 自动初始化、日志格式带 `[trace=%X{traceId:-none}]`。关键决策：日志 pattern 取的是 MDC 里的 `traceId`，不是打印参数。**改了会怎样**：把 `%X{traceId}` 去掉，Java 日志就不再带 trace，验收第 5 条的证据直接消失。

**`src/main/resources/schema.sql`** — 建 `idempotency(request_id PRIMARY KEY, response_json, trace_id, created_at)`。关键决策：**主键就是幂等键**（让数据库来保证唯一），trace_id 跟着一起落库（让「这条记录是谁触发的」在库层面可追）。**改了会怎样**：把 request_id 从主键降级成普通列，`INSERT OR IGNORE` 就失去冲突判定依据，幂等当场失效。

**`MockOaApplication.java`** — 启动入口；在 `SpringApplication.run` 之前把 SQLite 的父目录建出来。关键决策：sqlite-jdbc 会创建 `.db` 文件但**不会创建目录**，目录不存在会直接启动失败，所以 `Files.createDirectories` 必须前置。**改了会怎样**：删掉这两行，在干净仓库里第一次跑就会报 path does not exist。

**`web/TraceFilter.java`（本卡心脏）** — 解析（或生成）`X-Trace-Id` → 写入 MDC → 回显响应头 → 请求前后各打一行带 trace 的日志。关键决策：只认 UUID 形状；**合法值原样透传、不重写不改大小写**，非法/缺失才自己生成；回显发生在 `chain.doFilter` 之前，保证异常路径也有头。**改了会怎样**：① 把「原样透传」改成「重新生成」，Python 侧的等值断言立刻失败；② 漏掉 `finally` 里的 `MDC.remove`，线程池复用会把上一个请求的 trace 串到下一个请求上——这是排查线上事故时最经典的假线索。

**`config/OpenApiConfig.java`** — 给导出的契约写上 title / version / server。关键决策：契约版本 `0.1.0-P0-01` 显式写在代码里、与任务卡挂钩，不跟着 pom 的 SNAPSHOT 漂。**改了会怎样**：删掉它，`docs/contracts` 里就会出现一份 title 为 `OpenAPI definition`、version 为 `v0` 的契约文件（本轮第一次导出就是这个样子，见 §7 的改进记录），Python 侧没法据此判断版本。

**`api/HealthController.java`** — `GET /healthz` 只回 `{"status":"ok"}`。关键决策：不塞时间戳/版本号/依赖状态。**改了会怎样**：健康检查一旦带上业务信息，探活就会跟着业务一起抖，变成运维噪音源。

**`api/ApprovalController.java`** — `POST /api/mock/oa/approvals`；把 service 层的 dedup 结果映射成响应头 `X-Dedup`。关键决策：`X-Request-Id` 用 `required=false` 自己校验，而不是交给 Spring 抛 `MissingRequestHeaderException`。**改了会怎样**：改成 `required=true`，缺头时 Spring 会返回 400 + 默认错误体，破坏「所有错误统一形状」的契约。

**`api/FaultController.java`** — `GET/PUT /api/mock/faults`。关键决策：PUT 的响应体就是开关的当前状态（调用方不用再 GET 一次确认）。**改了会怎样**：返回 204，每个调用方都得多打一次 GET，而且拿不到「被上限截断后的真实值」。

**`api/dto/*.java`（5 个 record）** — `ApprovalRequest` / `ApprovalResponse` / `FaultRequest` / `FaultStatus` / `ErrorResponse`，线上字段名全 snake_case。关键决策：record + `@JsonProperty`（理由见 §6.3）；`FaultRequest` 用包装类型 `Integer/Boolean`。**改了会怎样**：`FaultRequest` 改成基本类型，Jackson 会把「没传的字段」填成 `0/false`，等于**没传就悄悄关掉开关**。

**`service/ApprovalService.java`** — 校验 → 故障延迟 → `INSERT OR IGNORE` → 冲突则回读首次结果并置 `dedup=true`。关键决策见 §6.1；回读带 20 次 × 50ms 重试兜底。**改了会怎样**：换成「先 SELECT 再 INSERT」，并发下会建出两条单（§5.9 的并发实测就是为钉死这一点）。

**`service/ApprovalResult.java`** — 服务层返回值 = 响应体 + 是否命中幂等。关键决策：dedup 同时出现在 body 和响应头，需要一个中间载体把它从 service 传到 controller。**改了会怎样**：让 service 直接去碰 `HttpServletResponse` 也能实现，但分层就烂了，后续 mock-finance / mock-scm 会跟着学坏。

**`service/FaultService.java`** — 内存故障开关；`timeout_ms` 上限 10000，`random_delay` 叠加 0–500ms 抖动。关键决策：`volatile` 双字段 + **重启即复位**（调试开关不该持久化）。**改了会怎样**：把它落库，上次调试留下的 5 秒延迟会变成下次演示的幽灵 bug。

**`error/ApiException.java` · `error/ErrorCodes.java` · `error/GlobalExceptionHandler.java`** — 业务异常 + 错误码常量 + 统一错误体（含 trace_id）。关键决策：错误体里也带 `trace_id`。**改了会怎样**：Python 侧拿到 422 时只能靠时间戳猜是哪次请求，跨服务排障成本立刻上去。

### 4.2 Python 侧与文档

**`python-service/pyproject.toml`** — uv 管理的工程定义（依赖 `httpx`，dev 依赖 `pytest`）。关键决策：不写 `[build-system]`，uv 当虚拟工程处理（只装依赖、不打包自身）。**改了会怎样**：补上 build-system，`uv sync` 会尝试构建并安装本目录，多一层无意义的打包配置。

**`python-service/tools/oa_client.py`（Python 侧心脏）** — `create_approval(...)` 生成 trace_id → 打 mock-oa → **断言响应头回显 == 自己生成的值**；另有 `check_health` 与 `__main__` 自测（含幂等双调用断言）。关键决策：trace 断言写在发请求的函数里（不满足就抛异常），而不是写在自测脚本里——这样任何调用方都躲不过检查。**改了会怎样**：把断言降级成 print，就变成「看起来验过了」；将来 Java 侧漏了回显，问题会一路潜伏到 P0-02 的联调现场。

**`README.md`（占位）** — 项目名 + 一句话 + 两条启动命令。**改了会怎样**：新克隆仓库的人（和面试官）第一眼不知道从哪跑起来。

**`docs/contracts/java-service-openapi.json`** — springdoc 从代码生成的契约快照，P0-02 的 Python 侧按它对接口。**改了会怎样**：Java 侧改了端点却不重新导出，这份文件就成了错误文档——比没有更坏，因为有人会信它。

## 6. 四个「为什么」（简报 §5 点名要的）

### 6.1 幂等表为什么用 `INSERT OR IGNORE` + `SELECT`

先讲清楚**不这么做会怎样**。直觉写法是「先查有没有，没有就插」（check-then-act）：

```text
SELECT ... WHERE request_id = ?   -- 两个并发请求都查到「不存在」
INSERT ...                        -- 于是两个都插，建出两条单
```

两个并发请求在两次操作之间互相穿插，**检查与写入之间的时间窗就是竞态窗口**，靠应用层锁去堵它是把自己变成数据库。

正确做法是把「唯一性」这件事交给数据库：`request_id` 是主键，所以

1. `INSERT OR IGNORE` 一定只有一个请求能成功插入（返回 1 行）；
2. 其余请求拿到 0 行 —— 这不是「插入失败」，而是**结论明确的信号：这个 request_id 之前来过**；
3. 然后 `SELECT` 回读那一行，把首次的 `approval_id/created_at` 原样回给对方，只把 `dedup` 翻成 true。

为什么不用 `INSERT ... ON CONFLICT DO UPDATE ... RETURNING`：它也能保证唯一，但返回的是「冲突后的行」，我们仍然要**区分这次到底是不是首次**（首次要回 dedup=false、要打不同的日志），两段式更直白，也更好在日志里看到「谁赢了」。

**并发下到底会发生什么**（本轮实测，见 §5.9）：

- 5 个并发同 request_id → 数据库层面只有 1 行；1 个响应 dedup=false，4 个 dedup=true；
- 回读理论上（连接池=1 时）永远能立刻读到；但仍写了 20×50ms 重试：因为「忽略冲突」与「提交对别人可见」之间依赖隔离级别与提交时序，把连接池从 1 放开、或将来换成 PG 之后，就有可能读到「还没有可见行」。重试把这种时序问题挡在实现内部，而不是变成偶发 500。

配套的两个决定：

- **连接池 = 1**：SQLite 是单写者，多个连接并发写只会换来 `SQLITE_BUSY`。对 mock 服务来说，用「串行」换「确定性」是划算的交易（P0-02 换 PG 时再放开）。
- **`busy_timeout=5000`**：万一仍有锁等待，让它等而不是立刻抛错。

### 6.2 为什么 `java.version` 必须是 21

Maven 的 `java.version` 最终体现在 javac 的 `--release` 上，而 `--release` **同时锁两件事**：语言级别 **和** 可用的 JDK API 面（它对着那个版本的 API 签名表编译，而不是对着当前 JDK 的 rt）。

所以写成 17 的后果不是「少用几个新语法」，而是 `Thread.ofVirtual()`、结构化并发（`StructuredTaskScope`）、`SequencedCollection` 这类 **21 才有的 API 直接变成「找不到符号」**——报错形态极具误导性，看起来像依赖缺失或拼写错误，实际是版本卡住了。

本项目 P0-01 用不到这些 API，但 P0-02 的流程执行/并发调度会用到（虚拟线程跑阻塞式 mock 调用是这一层最自然的写法）。**现在钉成 21，是为了不让版本问题在 P0-02 以「莫名其妙的编译错误」形式爆发。**

### 6.3 为什么要 `@JsonProperty` 保住 snake_case

跨语言契约里，**字段名就是 API 本身**，不是实现细节：Python 侧发的是 `request_id`，Java 侧接不住就是 422，没有中间地带。

Java 的习惯是 camelCase，record 组件名只能写 `requestId`。两种选择：

1. **全局命名策略**（`spring.jackson.property-naming-strategy=SNAKE_CASE`）：改一行配置就能让所有 DTO 全变 snake_case，看起来更「优雅」；
2. **局部 `@JsonProperty`**（本实现的选择）：每个跨边界字段显式标注线上名。

选 2 的理由是**隐式魔法的代价**：全局策略把「字段名」这件事藏进了配置，任何人（包括将来的我）加一个 `ObjectMapper` 定制 Bean、或者换个模块的 Jackson 配置，线上字段名就会静默改变，而且只在运行期、跨语言调用时才暴露。局部注解让「这个字段线上叫什么」在 DTO 定义处一眼可见；`ApprovalResponse` 里 `dedup` 这种本来就是单词的字段也不必被策略二次加工。

同理，`FaultRequest` 用包装类型而不是基本类型：Jackson 对缺失字段的默认行为是填 `0/false`，而契约语义是「没传 = 保持原值」——**类型选择本身就是契约表达**。

### 6.4 trace 为什么走 MDC，而不是层层传参

如果 trace_id 作为方法参数往下传：controller → service → 日志调用点，每一层都要多一个参数；而且任何一处忘带，日志就断链。更糟的是**异常路径**——错误处理、重试、异步回调里根本没有那个参数。

MDC 是「本次请求的隐式上下文」：`TraceFilter` 在进入时 `put`、在 `finally` 里 `remove`，中间任何一层的 `log.info(...)` 都会自动带上 `[trace=...]`，包括 `GlobalExceptionHandler` 里打的错误日志。代价是**它是 ThreadLocal，绑定线程**：一旦上异步/线程池就要显式传递（P0-02 引入异步执行时需要处理，届时会把 trace 放进任务包装器里）。这条边界值得提前知道。

## 7. 我做的补充决定（简报没钉死，请 Hermes 复核）

| # | 决定 | 理由 |
|---|---|---|
| 1 | `X-Request-Id` 必须与 `body.request_id` 一致，不一致 → 422 | 契约里幂等键有两个来源（头 + 体），若允许不一致，就会出现「头说 A、体说 B」时幂等按谁算的争议 |
| 2 | 首次响应也显式返回 `X-Dedup: false` | 只靠「有头 = 重复」不够明确；显式 false 让调用方与断言都能对称处理 |
| 3 | `timeout_ms < 0` → 422；`> 10000` → 截断为 10000 并 WARN | 简报只写了「上限 10000」，我选择「负值报错、超限截断」并在日志留痕 |
| 4 | `random_delay=true` 的抖动范围定为 0–500ms | 简报只给了字段名，未给范围；0–500ms 足以制造非确定性，又不至于拖垮自测 |
| 5 | `PUT /api/mock/faults` 字段为 `null`（或空 body）= 保持原值 | 局部更新语义；与「基本类型默认 0/false」的坑配套 |
| 6 | 故障延迟只作用于 mock 写端点（POST approvals），不打在 `GET /api/mock/faults` 上 | 否则「关闭开关」这个动作本身也要等 5 秒，调试体验灾难 |
| 7 | 新增 `python-service/uv.lock` | uv 生成的锁文件，保证 httpx 版本跨机器可复现；**超出「pyproject + oa_client.py」的字面范围**，若不需要可直接删 |

另外两处提请注意：错误体里的 `trace_id` 取自 MDC（即当前请求的 uuid）；`GET /healthz` 也会被 TraceFilter 记录（含访问日志）。

## 9. 环境坑实录（本轮真实踩到的，给后续会话省时间）

1. **XML 注释里不能出现连续两个减号**：pom 注释里写了 `--release`，Maven 直接 `Non-parseable POM` 报错。改成「javac 的 release 开关」即可。
2. **Maven 必须全路径**：`D:\software\maven-dist\apache-maven-3.9.9\bin\mvn.cmd`；且本次会话的文件沙箱默认不允许写工作区外的 `~/.m2`，Maven / uv 都会被拦（`AccessDeniedException` / `拒绝访问`）。放开文件策略后一切正常，与 Maven 本身无关。
3. **curl 打本机也要 `--noproxy "*"`**：环境里存在 `http_proxy=127.0.0.1:7897`，不加这个参数请求会被导去代理。
4. **Python 打印中文要 `PYTHONUTF8=1` + `PYTHONIOENCODING=utf-8`**：否则写进 txt 的日志是 GBK，后续读出来是乱码。
5. **`springdoc` 版本取 2.8.17**（Boot 3.5 兼容线里镜像上的最新 2.8.x）；`sqlite-jdbc` 用 3.53.4.0（本地缓存已预热）。
