## 2. A1 — 回归套件：修编码 + 收录

### 2.1 根因

套件把**含中文的 JSON 当参数传给 `curl.exe`**。Windows 下 PowerShell 把原生命令参数按 **ANSI(GBK)** 转换，Java 收到的是非法 UTF-8，Jackson 直接判请求体坏了：

```text
malformed json body: Invalid UTF-8 start byte 0xbd      # 0xbd 是「姜」的 GBK 首字节
```

表现是含中文 payload 的 6 条用例 422 —— 看起来像服务端校验错了，其实是**调用侧编码**问题。这类 bug 最贵的部分是"它长得像业务问题"。

### 2.2 修法（两个动作，不是一个）

1. **常规 payload 一律 ASCII**（`applicant=tester`）：把"命令行参数编码"这个不确定性从 20 条用例里彻底移走；
2. **保留一条 UTF-8 用例**（第 5 项）：body 写成 UTF-8 文件，用 `curl -d @file` 发送 —— 中文 payload 的跨语言链路仍被验证，而且走的是**文件字节**，不经过命令行参数的编码转换。

为什么不是"直接删掉中文用例"：那会把"能处理非 ASCII"这条性质从回归里抹掉。修法②让这条性质留下，同时把脆弱性去掉。

### 2.3 收录与包装

- `scripts/p0-02-regression.ps1`：套件本体（21 项断言，退出码 = 结果）；
- `scripts/run-regression.cmd`：包装器（`chcp 65001` + **pwsh 绝对路径** `C:\Program Files\PowerShell\7\pwsh.exe` + `-NoProfile -File`，`-BaseUrl` / `-Label` 透传）；
- `scripts/pg-checks.ps1`：PG 侧库内校验 + append-only 权限探针（密码只从本地未提交文件读，不打印）；
- `README.md`：新增"回归测试"一节。

另一个细节：套件的临时文件改到 `$env:TEMP` 下，不再写进脚本所在目录 —— 收录进仓库后，脚本目录是受版本控制的工作区，不该被运行产物污染。

## 3. A2 — 三张表 + Java 接口层

### 3.1 schema（两份都改）

| 表 | 关键设计 | 为什么 |
|---|---|---|
| `idempotency` | 沿用 P0-01（`request_id` 主键） | 幂等语义没变，不动它 |
| `flow` | `id TEXT PK` + `request_id TEXT NOT NULL UNIQUE` | 业务 id 用字符串而不是自增：`AUTOINCREMENT` / `IDENTITY` 是方言差异重灾区，而且跨服务传递需要的是可读的业务 id；`UNIQUE` 是"同 request_id 只建一张单"的数据库级保证 |
| `audit_log` | `audit_id TEXT PK` + 可空列 `detail` / `trace_id` | 只追加、不修改；`trace_id` 一列让审计能与 Java 日志、Python trace 三方对账 |

时间字段一律 `TEXT` + ISO-8601 字符串（与 HTTP 契约一致，跨库跨语言零类型映射；取舍见 P0-02 §0 讲解 §5.4）。

**PG 文件比 SQLite 文件多出的那一段**：

```sql
REVOKE UPDATE, DELETE, TRUNCATE ON audit_log FROM CURRENT_USER;
```

两处刻意选择：

- **用 `CURRENT_USER` 而不是写死 `p2p_agent`**：应用角色来自配置占位符（`PG_USER`，默认 `p2p_agent`）。写死角色名在换角色时会静默失效（REVOKE 一个不存在的角色 → 报错或什么也没做），而 `CURRENT_USER` 永远是"正在连库的那个角色"。
- **连 `TRUNCATE` 一起收**：它在 PG 里是**独立权限**，一条 `TRUNCATE` 就能清空全部审计 —— 只堵 `DELETE` 会留下一个显眼的后门（这正是面试官爱追的一刀）。

### 3.2 逐文件讲解（做什么 / 为什么 / 改了会怎样）

**`api/dto/FlowView.java`** — 流程实例的对外形状（9 个字段，snake_case）。**为什么 `state` 是 String 而不是 FlowState 枚举**：接口层必须能在 `engine/FlowState`（[你敲]）落地之前编译；而且枚举一旦进了 DTO，Jackson 的序列化行为（用名字还是序号）就悄悄变成跨语言契约的一部分。**改了会怎样**：换成枚举，Python 侧就得猜"这个字段是名字还是数字"，而且你每给 `FlowState` 加一个状态都在改契约。

**`api/dto/CreateFlowCommand.java`** — 服务层入参（`item/qty/reason/costCenter`），**刻意不含 `request_id`**：request_id 是"这次请求的身份"，不是"要建一张什么单"。**改了会怎样**：把 request_id 塞进命令对象，服务层就会同时握着"业务参数"和"传输身份"两种东西，幂等逻辑会长进业务逻辑里。

**`api/dto/CreateFlowRequest.java`** — 线上 body（比命令对象多一个 `request_id`）。**为什么需要它**（简报清单里没有，是我加的，见 §7 决定 2）：契约规定 body 带 `request_id`，而 Controller 必须校验它与 `X-Request-Id` 一致 —— 不解析它就无从校验。**改了会怎样**：直接拿 `CreateFlowCommand` 当 body 接，`request_id` 就没人校验，"头说 A、体说 B"的脏请求会直接进业务层；`qty` 用 `Integer` 同理 —— 缺字段要能给出准确的 422，而不是静默变成 0 台。

**`api/dto/RejectFlowRequest.java`** — 驳回体 `{reason}`。理由必须落进审计 `detail`，否则"为什么被驳回"在系统里查不到。

**`api/dto/AuditView.java`** — 审计一行（7 字段）。没有任何可变入口；`action` 用 String（理由同上）。

**`db/FlowRepository.java`** — `flow` 表唯一出入口：`insertFlow` / `findById` / `findByRequestId` / `updateStateIfCurrent`。**核心是条件更新**（§6.2 展开）。两条 SQL 都是两库共通子集，所以两个 profile 跑的是同一份代码。**改了会怎样**：把条件更新换成"先查再改"（`SELECT state` → 判断 → `UPDATE`），并发下两个审批人都能读到 `PENDING_APPROVAL`，状态被推进两次、审计出现两条重复行 —— 而且**低并发测试里永远复现不出来**。

**`db/AuditRepository.java`** — 只有 `insert` 与 `listByFlow`，**没有 update / delete**（§6.3 展开）。

**`web/FlowController.java`** — 5 个端点。Controller 只做三件事：取头、做形状校验、调 `FlowService`；**不做状态判断**（能不能 A→B 是状态机的事，写进 Controller 就再也穷举不了）。三个刻意选择见 §7 决定 6。

**`engine/FlowService.java`（占位接口）+ `engine/FlowServiceStub.java`（占位桩）** — 让你在动手写实现之前，web 层就能编译、能启动、能被 curl 打通。桩回答 **501 NOT_IMPLEMENTED** 而不是假数据：**没实现就说没实现**，比返回一个看起来成功的空对象安全（否则前端会以为下单成功了）。**阶段 B 请删除 `FlowServiceStub.java`**：把 `FlowService.java` 改成你的 `@Service class` 即可（留着它的报错很明确："found 2 beans" 或 "FlowService is not an interface"）。

**`mockoa/error/ErrorCodes.java` / `ApiException.java`（改）** — 补 `FLOW_NOT_FOUND`(404) 与 `NOT_IMPLEMENTED`(501)，并给 `ApiException` 加 `conflict` / `notFound` / `notImplemented` 工厂。**为什么沿用 `com.p2pagent.mockoa.error` 而不新建 `com.p2pagent.error`**：见 §7 决定 4（一句话：全局异常处理器只能有一个）。

**`src/test/java/com/p2pagent/db/FlowRepositoryTest.java`（新，简报清单外）** — 6 个用例，把两件"别人要靠的地基"钉住：条件更新只有第一个调用者拿到 1；`AuditRepository` 上不存在 update/delete 方法（反射断言，见 §6.3）。**改了会怎样**：这两个行为没有测试，就只能靠"我记得是这样的" —— 而阶段 B 的 409 逻辑整个建立在它们之上。

## 4. A3 — Python 接口层

### 4.1 `llm/deepseek.py`

钉死的接口：`complete_json(system, user, schema, *, model="flash") -> dict`。三层护栏：

1. **JSON mode**（`response_format={"type":"json_object"}`）：让模型在解码层面只能产出 JSON 对象；
2. **schema 提示**：JSON Schema 原样贴进 system。**注意 DeepSeek 的 json_object 模式并不校验 schema** —— 它只是很强的提示，真正的校验在调用方（Pydantic）。注释里写明这一点，是为了不让人误以为这里已经验过了；
3. **重试一次**（退避 0.5s）：超时 / 5xx / 解析不出对象都走同一条路径；两次都失败就抛 `DeepSeekError`。**不静默降级成 `{}`** —— 空字典会被上层当成"模型说没有参数"，那是把网络故障伪装成业务结论。

模型别名 `flash` / `pro` → `deepseek-flash` / `deepseek-v4-pro`（真实型号，用 `/models` 端点查出来的，不是猜的），可用环境变量覆盖；key 从 `python-service/.env` 读（gitignored），环境变量优先。

`.env` 用手写 8 行解析而不是引 `python-dotenv`：我们只要 `KEY=VALUE` / `# 注释` / 忽略空行这一种子集，而 python-dotenv 还带插值、多文件合并等行为 —— 多一种行为就多一份"为什么这里读到的是那个值"的解释成本。

### 4.2 `trace/tracer.py`

`record(trace_id, step, payload) -> None`：写 `<repo>/trace/<trace_id>.jsonl`，一行一个 JSON。

**为什么是 JSONL 而不是数据库**：追加写 + 一行一记录 = 崩溃最多丢最后一行；纯文本可 grep、可直读。Java 侧审计落库（要按单查、要权限保护），Python 侧 trace 落文件（要看细节、要快），两边靠**同一个 trace_id** 对账。

**失败语义刻意不对称**：目录建不出来 → 抛 `TracerError`（配置/权限坏了，早失败）；单次追加失败 → 只打警告、不打断业务（可观测性不该成为业务故障的来源）。加锁是为了防"两行交叠成半行" —— 不可解析的 trace 等于没记。

### 4.3 `tools/flow_client.py`

5 个方法对应 5 个端点，沿用 P0-01 `oa_client.py` 的三个做法：**trace_id 由调用方传入**（一次请求一个 trace）、**每次调用断言 `X-Trace-Id` 原样回显**、**非 2xx 抛结构化 `ContractError`**（带出 Java 的 `code` / `message` / `trace_id`，让 agent loop 能按 409 / 404 / 422 / 501 分别决策）。

## 5. A4 — 启动类上移 + `data/` 目录 profile 化

### 5.1 为什么 A4 排在 A2 前面

`@SpringBootApplication` 只扫描**它自己所在包及子包**。启动类原来在 `com.p2pagent.mockoa`，那么 `com.p2pagent.engine` / `.db` / `.web` 里的 `@Service` / `@Repository` / `@RestController` **根本不会被扫到**，症状是启动后 "no qualifying bean"（不是编译错误，排查会绕远路）。

A2 新写的 `FlowController` 就住在 `com.p2pagent.web` —— **不先移扫描根，A2 的端点根本不会存在**，也就无从验收。所以实际顺序是 A1 → A4 → A2 → A3。

### 5.2 `data/` 目录只属于 sqlite

旧逻辑在 `main` 里无条件建 `data/`：PG profile 下会留下一个空目录（无害但脏）。新逻辑改为读**解析后的 JDBC URL**：

- 为什么看 URL 而不是判断 profile 名字：URL 是配置的**最终结果**（profile 默认值、命令行覆盖、`APP_DB_PATH` 全都在里面），比"猜当前是不是 sqlite profile"更接近事实，顺带成为 db 路径的唯一真相来源；
- 为什么用 `ApplicationEnvironmentPreparedEvent` 而不是 `@PostConstruct` / `@Bean`：建目录必须发生在 DataSource 初始化**之前**，而这个事件在 environment 就绪之后、context refresh 之前发布 —— 唯一"够早且拿得到配置"的时机。

## 6. 三个专题（简报 §4 最后一条要求）

### 6.1 为什么"先交接口层"

1. **依赖方向决定顺序**。你要写的 7 个文件是"调用方"：`FlowService` 依赖 `FlowRepository` 与 DTO，`agent.py` 依赖 `deepseek.complete_json` 与 `tracer.record`。调用方先写，签名就得猜；写完对不上，返工的是**你要亲手写的那部分**（最贵的部分）。被调用方先钉死，你写的时候只需要想业务。
2. **接口层能独立验收**。本阶段不用等你的实现就已经能证明：建表对不对、错误体形状对不对、trace 透不透、404 / 422 是不是按契约返回。这些是地基，它们的验收不该和业务逻辑混在一次交付里。
3. **桩要说真话**。没实现就 `501 NOT_IMPLEMENTED`（而不是假成功）。这样"接口通了但业务没通"在 curl 输出里一眼可见 —— 面试时这也是个能讲的点：**如何让"未实现"与"已完成"在语义上不可混淆**。

### 6.2 条件更新与幂等的关系（本项目最值得讲的一段）

两个问题看起来不同，其实是同一个问题的两面：

| | 幂等（P0-01 的 `idempotency`） | 乐观锁（P0-02 的 `flow.state`） |
|---|---|---|
| 防的是 | **同一个请求**重复到达（网络重试、用户连点） | **不同请求**竞争同一个资源（两个审批人同时点同意） |
| 判据 | `INSERT ... ON CONFLICT DO NOTHING` 的**影响行数** | `UPDATE ... WHERE id=? AND state=?` 的**影响行数** |
| 拿到 0 行意味着 | 这个 request_id 之前来过 → 回读原结果返回 | 状态已被别人改过 → **409 FLOW_STATE_CONFLICT** |

**共同的手法**：把"我是不是第一个"交给数据库的原子操作，而不是应用层的"先查后改"。应用层的时间差在单机低并发下几乎不暴露，一旦并发上来就是数据错乱 —— 而且错乱方式是"多了一条审计""状态被推进两次"，都是最难查的那类。

**落地位置**：`FlowRepository.updateStateIfCurrent` 只返回影响行数、**不抛异常**；是不是 409、message 里带什么排障信息，由 `FlowService`（你的文件）决定。仓储层保持"纯粹的数据操作"，业务语义留在编排层 —— 面试问"这一层为什么不抛异常"就有得答。

### 6.3 审计 append-only 的三层保障

"append-only 你怎么保证，不只是嘴上说？" —— 分三层答，**每一层都能在代码或证据里指出来**：

| 层 | 手段 | 本项目的证据 |
|---|---|---|
| 代码层 | 写入口**结构上不存在**修改能力：`AuditRepository` 只有 `insert` 与 `listByFlow` | 单测用反射断言"没有任何 update / delete 方法" |
| 数据库层 | PG `REVOKE UPDATE, DELETE, TRUNCATE ON audit_log` —— 越权改动**被数据库拒绝** | `\d` 后的权限表 + 三条被拒探针（§3.3） |
| 业务层 | 状态迁移与审计写入**同一事务**（`@Transactional`，由你的 FlowService 落地）+ 每次迁移必写一条 → 演进方向是事件溯源（状态可由审计重放得出） | 待阶段 B 实现后验证 |

**这条分级本身就是高分回答**：它区分了"制度"（我们约定不改）与"机制"（改了会被拒绝）。而 SQLite 只能做到第一层 —— 这正是双 profile 除了性能之外的教学价值：**同一个设计目标，两种存储能提供的保障强度不同**。

## 8. 已知边界 / 未验证

### 8.1 ⚠️ 验收条目"非法迁移返回 409"在阶段 A **无法实测**

原因不是"没做"，而是**这一条的产生逻辑就在你要写的文件里**：409 由 `FlowService`（编排）+ `FlowStateMachine`（迁移表）共同产生，两者都是 `[你敲]` 文件，阶段 A 不能替你实现。我没有伪造一个 409 输出。

阶段 A 能给出的、离它最近的真实证据是**判据本身**：条件更新在"预期状态过时"时返回 0 行（单测 `updateStateIfCurrentLosesWhenExpectedIsStale`），而 FlowService 拿到 0 就该抛 409。**阶段 B 你实现完后**，这条命令就能看到 409：

```bash
# 前提：用你实现的 FlowService 建出一张 PENDING_APPROVAL 的单，然后连续审批两次
curl -s -i -X POST http://127.0.0.1:8000/api/flows/flow-xxxx/approve -H "X-Operator: alice"   # 第一次 200，状态推进到 COMPLETED
curl -s -i -X POST http://127.0.0.1:8000/api/flows/flow-xxxx/approve -H "X-Operator: bob"     # 第二次应 409 FLOW_STATE_CONFLICT
```

### 8.2 其他边界

- **PG 侧是"清表后由 schema 重建"**，不是"全新空数据库"（`DROP TABLE` 后启动重建，等价于建表路径，但不等于空库路径）；真空白库留到 P1 做 CI 时补；
- **`pydantic` 没有加进 `pyproject.toml`**：它是你的 `agents/intent.py` 要用的依赖，按你的规格由你 `uv add`（我不越界改依赖清单）；
- **`flow_step` 表未建**（简报 §A2 明确本卡不建，留 P0-03）；
- **audit 端点的 404 语义**：单据不存在时返回 404（而不是空列表）—— "空列表"与"单据不存在"是两件事，前者会让前端把"查错了单号"当成"这单没有审计"；
- **501 会出现在正常演示里**：只要 `FlowServiceStub` 还在，POST / approve / reject 都是 501 —— 这是刻意让"未实现"显形，阶段 B 完成即消失。

## 9. 环境与协作坑（本轮新增）

1. **`trace/` 包名撞标准库**：没有 `__init__.py` 时 `from trace.tracer import record` 报 `No module named trace.tracer; trace is not a package` —— Python 的命名空间包（PEP 420）**优先级最低**，解析器会继续往后找，标准库里的常规模块 `trace` 赢了。加 `__init__.py` 变成常规包后按路径顺序先命中。**更稳妥的办法是改名 `tracing/`**，本卡因为规格钉了 `trace/` 所以保留。
2. **`python script.py` 的 `sys.path[0]` 是脚本目录、不是 cwd**：把自测脚本放在 `target/` 下用 `uv run python <绝对路径>` 跑时，`import llm.*` 会失败（`ModuleNotFoundError`），要加 `PYTHONPATH=.` 或改用 `python -m`。
3. **`mvn clean` 会清空 `java-service/target/`**：上一轮它把放在那里的回归套件清掉过一次（表现为 `pwsh -File` 报"无法识别为脚本文件名"）。这也是本卡把套件收录进 `scripts/` 的原因之一。
4. **协作提醒（本轮真实发生）**：你在并行编辑 `engine/FlowState.java`，中途有一次**保存瞬间的语法错误**（缺 `,` 与 `;`）让服务起不来（`Compilation failure`），我重试后正常。另外，我的一次 `git commit` 因为该文件当时**已被暂存**而被顺带提交，我立刻 `git reset --soft HEAD~1` + 只保留自己的 4 个文件重新提交（`e93dc5d`）。**此后我所有提交都改为"显式列出文件路径 + 提交前打印 `git diff --cached --name-only` 核对"**，避免再卷进你的文件。
5. **`curl` 打本机要 `--noproxy "*"`**（环境里有 `127.0.0.1:7897` 代理）；**PS7 里 `(if ...)` 不是表达式**（赋值可以、当实参不行），断言函数因此丢过一次明细行。
