## 0. 一句话主线（全项目的枢轴）

> **一个自然语言意图，要跨两个进程、穿过若干个失败点，最终"只发生一次"，而且全程可追。**

这半句里有两个词撑起了整个架构：

| 词 | 技术实体 | 管什么 |
|---|---|---|
| **只发生一次** | `request_id` 幂等 | 网络重试 / 用户重复点击 **不等于**重复下单 |
| **全程可追** | `trace_id` 全链路透传 | 跨进程排障有一条可以 grep 到底的线 |

后面 P0-02 的状态机、HITL、审计**都是这两个地基上的场景扩展，不是新概念**。

## 1. 项目是什么

| 层 | 内容 |
|---|---|
| 业务壳 | 采购到付款（P2P）：一句话说"我要买 1 台 MacBook 给新人用" → 预算校验 → 审批 → 下单 → 验收 → 付款 |
| 技术内核 | **流程执行型 Agent**：规则主干（确定性）+ 模型分支（不确定性）；高风险动作必须人批（HITL） |
| 为什么选这个业务 | 天然含"花钱"这个高风险动作 → 逼出审批 / 审计 / 幂等 / 补偿这些**真问题**，而不是玩具 demo |

## 2. 为什么拆成两条服务（面试第一问）

| | Python 侧（主干，:8001） | Java 侧（企业侧，:8000） |
|---|---|---|
| 管什么 | **不确定**的决策：意图解析、澄清追问、规则外判断、模型路由 | **确定**的账：状态机、幂等、审计、审批节点、错误码 |
| 技术 | FastAPI + 自研 ReAct harness + DeepSeek 路由 | Spring Boot 3 + JDK 21 + JDBC（SQLite 默认 / PG 可选） |
| 为什么 | LLM 生态、Pydantic 结构化输出、迭代快 | 事务 / 状态机 / 审计是 Java 主场，工程规范被面试官认 |
| 怎么连 | HTTP + OpenAPI 契约；`request_id` / `trace_id` 全链路透传；契约快照入库 `docs/contracts/` | |

**话术**：「确定性的资金流程交给 Java 工程，不确定性的模型决策交给 Python AI 生态」——与 JD 的"确定性工程 + AI 工程"运行时拆法一致。

## 3. 把零件串起来：一次请求的一生（8 步）

| # | 步骤 | 代码位置 | 为什么这么设计 |
|---|---|---|---|
| ① | Python 生成 `trace_id`（uuid4） | `python-service/tools/oa_client.py · new_trace_id()` | 身份证由**调用方**生成，不是被调方生成后告诉它 |
| ② | 两个头出发：`X-Trace-Id` + `X-Request-Id` | 同上 | 一个管"这次调用是谁"，一个管"这次业务只许发生一次"，两件事分开 |
| ③ | Java 进门：**原样透传** + 写 MDC + **先设响应头** | `web/TraceFilter.java`（`@Order(HIGHEST_PRECEDENCE)`） | 重写就断链（Python 断言必挂）；先设头保证**异常路径也有 trace** |
| ④ | 校验 → 故障延迟 → 幂等写入 | `service/ApprovalService.java · createApproval()` | 顺序刻意：参数错立刻 422，不让调试者白等 5 秒 |
| ⑤ | 数据库靠主键判唯一 | `resources/schema.sql · idempotency(request_id PK, …)`；`INSERT … ON CONFLICT DO NOTHING` | **影响行数就是答案**：1=首次，0=之前来过；唯一性交给数据库 |
| ⑥ | 0 行 → 回读首次结果，dedup=true | `ApprovalService · selectStored()`（20×50ms 重试兜底） | 返回首次的 `approval_id`/`created_at` = 幂等的字面含义 |
| ⑦ | 响应头回显 + `X-Dedup` | `api/ApprovalController.java` | 调用方无需解析 body 就知道是否重复 |
| ⑧ | Python 断言：回显 == 自己生成的？ | `oa_client.py · _post_approval()`（不满足抛 `TracePropagationError`） | 断言写在**发请求的函数里** → 任何调用方都躲不过；静默通过 = 没验 |

### trace_id 贯穿的 5 个落点（"跨语言可观测性"）
1. 请求头 `X-Trace-Id` → 2. Java MDC → 每行日志 `[trace=…]` → 3. 幂等表 `trace_id` 列（落库可追）→ 4. 响应头回显（当场可验）→ 5. Python 侧断言（不满足就抛错）

### 证据三件套（能"证明"而不是"声称"）
- **日志**：同一个 uuid 在 Java 控制台可 grep（`trace_source=incoming`）
- **数据库**：同 `request_id` 只有 1 行；`trace_id` 列就是 Python 生成的那串
- **契约文件**：`docs/contracts/java-service-openapi.json` 与运行实例 `diff` 一致

## 4. 五个零件「没有它会怎样」

| 零件 | 有它 | 没它 |
|---|---|---|
| `TraceFilter` + MDC | 每行日志自带 trace，一条链路 grep 到底 | 跨进程排障靠猜时间戳 |
| `idempotency` 表 | 重复请求返回**首次结果** + `X-Dedup: true` | 网络重试 = 重复下单 = 赔钱 |
| 统一错误体 `{error:{code,message,trace_id}}` | 错误也带 trace，拿到 422 直接定位 | 排障成本翻倍 |
| 故障开关（timeout / random_delay） | 主动制造"慢下游"，重试/补偿才有戏可演 | 只能"声称"能容错 |
| 契约快照 json | Java 改了端点，Python 有唯一真相可对 | 过期文档比没文档更坏（因为有人信） |

## 5. 三条日常规矩（IDE 与构建工具的关系）

1. **pom.xml 是真源，IDE 的模块是它的投影**。改 pom（加依赖/改版本）→ 必须去 IDEA Maven 工具窗 **Reload All Maven Projects**；这就是"命令行 `mvn` 能编、IDE 满屏红"的根因。
2. **`.idea/` 与 IDEA 的外部存储都不入库**（`.gitignore` 已覆盖）：它们是**可再生的投影**，删掉重新右键 pom 就全回来。真源（pom + 代码 + docs）才进 git。
3. **命令行与 IDE 跑的是同一份定义**：同一主类、同一套依赖、同一 JDK，区别只是"谁算 classpath、谁起 JVM"。所以构建行为要写进定义（例：pom 里把 `spring-boot:run` 的 `workingDirectory` 钉死在 `java-service/`），而不是靠人的操作习惯。

## 6. 工程方法也是作品的一部分

流程：**任务卡（验收先行）→ 代码分档（`[你敲]` / `[dsh写+讲]` / `[dsh写]`）→ 《讲解.md》（逐文件"改了会怎样"）→ 独立审核 → 一卡一 commit**。

"独立审核"的含义（不是走过场）：**不采信执行方的自测结论** —— 从提交内容克隆 → 重新编译 → 换端口换库起实例 → 自己写断言跑 → 自己查库 → 自己 grep 日志 → 契约文件与运行实例 diff。

面试价值：被问"你怎么保证质量"时，答的不是"我觉得没问题"，而是一条**可复现的证据链**。

## 7. 面试 3 分钟故事线

> 一句话 → 谁决定步骤（规则主干 + LLM 分支）→ **为什么自研状态机而不是 Flowable/LangGraph**（可审计 / 可回滚 / 可测试）→ **HITL 边界**（钱必须人批）→ **为什么两门语言**（JD 同款拆法 + 跨语言 trace 是加分叙事）→ **故障怎么活**（重试 / 补偿 / 升级）→ **怎么证明有效**（Eval 数字）→ 审计回放演示

**必答三题**
1. **为什么不用 RAG**：P2P 是动作执行场景，决策信息在结构化单据里，不需要非结构化知识检索（扩展点=供应商知识库工具）。
2. **为什么不用现成工作流引擎**：花钱动作不交给黑盒；自研换可审计/可回滚/可测试；已做主流方案认知对照。
3. **为什么两套存储**（v0.3 新增）：SQLite = 零依赖可复现（clone 即跑、CI 无外部依赖）；PG = 生产级能力（并发写 / 行锁 / JSONB / **权限级 append-only 审计**）；同一套 DAO 用 profile 切换、SQL 只写两边通用子集。
