- **审计流水的并列时间戳 → 顺序不确定**（2026-10-19 实跑发现）
  - 现象：真建一张单（`req-ccbec347`）后，`GET /api/flows/{id}/audit` 返回的顺序是
    `FLOW_CREATED → APPROVAL_REQUESTED → SUBMITTED`，与预期（按发生顺序）不符。
  - 根因：`AuditService.append` 两次 `Instant.now()` 落在**同一时钟刻度**，库里 `at` 完全相同
    （实测 `...076860500Z` 出现两次）→ `ORDER BY at` 并列时 SQLite 返回顺序不保证。
  - 影响：审计展示可能偶发乱序；"按时间升序"这个承诺在同刻度时失效。
  - 三种修法（P0-03 处理，**未擅自改代码**）：
    ① `ORDER BY at, rowid` —— 只有 SQLite 适用，PG 无 `rowid`（破坏"SQL 只写共通子集"）；
    ② 给 `audit_log` 加 `seq INTEGER`（进程内 `AtomicLong` 生成，**不用数据库自增**，避开双库方言；需处理重启后归零）；
    ③ 应用层保证 `at` **严格单调**（维护 `lastAt`，新值 ≤ 上次则 +1µs）—— 改动最小，且不碰 schema。
  - 建议：先做 ③（一行比较 + 一个静态变量，配合 `synchronized`/锁），P0-03 若要加强再上 ②。
