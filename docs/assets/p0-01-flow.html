P0-01 「一次请求的一生」

绿点 = 真实发生的步骤；等宽字 = 代码位置（本仓库真实文件）｜ 配套文字：docs/串讲.md
Python
① 生成 trace_id（uuid4）
python-service/tools/oa_client.py · new_trace_id() 身份证由调用方生成，不是被调方生成后回头告诉它
HTTP
② 两个头出发
X-Trace-Id（链路身份证） + X-Request-Id（幂等键） 一个管"这次调用是谁"，一个管"这次业务只许发生一次"——两件事
Java
Web 层
③ 过滤器接住：原样透传 + 落 MDC + 先设响应头
web/TraceFilter.java · @Order(HIGHEST_PRECEDENCE) 合法就原样透传（重写则 Python 断言必挂）；非法/缺失才自己生成；先设响应头 → 异常路径也有 trace
Java
业务层
④ 校验 → 故障延迟 → 幂等写入
service/ApprovalService.java · createApproval() 顺序刻意：参数错立刻 422（不让调试者白等 5 秒）→ 注入延迟 → 写库
SQLite
⑤ 靠主键抢唯一：INSERT … ON CONFLICT DO NOTHING
resources/schema.sql · idempotency(request_id PK, response_json, trace_id, created_at) 影响行数就是答案：1 = 首次；0 = 这个 request_id 之前来过。唯一性交给数据库，不靠"先查再插"
Java
业务层
⑥ 0 行 → 回读首次结果，dedup 翻成 true
ApprovalService · selectStored()（20×50ms 重试兜底） 返回首次那条的 approval_id / created_at = 幂等的字面含义：重复调用，世界只发生一次
回程
⑦ 响应头回显 + 去重标记
X-Trace-Id（= Python 发来的那串） · X-Dedup: true/false 调用方当场可验证链路；不解析 body 就知道这次是不是重复
Python
⑧ 断言：回显 == 自己生成的？
oa_client.py · 不满足直接抛 TracePropagationError 断言写在发请求的函数里（不是自测脚本里）→ 任何调用方都躲不过；静默通过等于没验
贯穿物：trace_id 的 5 个落点 —— 这就是"跨语言可观测性"
① 请求头 X-Trace-Id ② Java MDC → 每行日志 [trace=…] ③ 幂等表 trace_id 列（落库可追） ④ 响应头回显（当场可验） ⑤ Python 断言（不满足就抛错）

证据三件套（能"证明"而不是"声称"）

  • 日志：同一 uuid 在 Java 控制台可 grep（trace_source=incoming）
  • 数据库：同 request_id 只有 1 行；trace_id 列 = Python 生成的那串
  • 契约文件：docs/contracts/java-service-openapi.json 与运行实例 diff 一致

故障开关为什么是"零件"不是玩具

  • 制造"慢下游"（sleep 5s）→ 逼出真实超时场景
  • 让 P0-02 的重试/退避、P1 的补偿有东西可演示
  • 只打死写端点，不打"关开关"本身（否则调试体验灾难）
主线：一个自然语言意图，要跨两个进程、穿过若干个失败点，最终"只发生一次"，而且全程可追。
"只发生一次" = request_id 幂等 ｜ "全程可追" = trace_id 透传 —— P0-02 的状态机/HITL/审计都是这两个地基上的场景扩展。
